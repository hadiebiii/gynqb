## ساختار نهایی ریپوزیتوری
پروژه با ساختاری بسیار ساده، سبک و بدون نیاز به Backend یا ابزارهای Build پیچیده پیاده‌سازی شده است:

```text
gynqb/
├── final/
│   ├── all_unique_questions.jsonl       # منبع جامع ۱٬۶۰۸ سؤال
│   ├── board_1403.jsonl                 # سؤالات بورد ۱۴۰۳
│   ├── ertegha_1402.jsonl               # سؤالات ارتقای ۱۴۰۲
│   ├── ertegha_1403.jsonl               # سؤالات ارتقای ۱۴۰۳
│   ├── ertegha_1404.jsonl               # سؤالات ارتقای ۱۴۰۴
│   ├── fellowship_endoscopy_1403.jsonl  # فلوشیپ اندوسکوپی ۱۴۰۳
│   ├── fellowship_infertility_1403.jsonl # فلوشیپ نازایی ۱۴۰۳
│   ├── fellowship_maternal_fetal_1403.jsonl # فلوشیپ طب مادر و جنین ۱۴۰۳
│   └── fellowship_oncology_1403.jsonl   # فلوشیپ انکولوژی ۱۴۰۳
├── docs/
│   ├── index.html                       # وب‌سایت اصلی (سیستم آزمون و مرور)
│   ├── admin.html                       # پنل مدیریت سمت مرورگر (ویرایشگر داده)
│   ├── questions.json                   # داده‌های نرمال‌شده نهایی سؤالات
│   └── CNAME                            # دامنه سفارشی (در صورت وجود)
├── .gitignore                           # فایل‌های نادیده‌گرفته‌شده توسط گیت
├── prompt.md                            # دستورالعمل‌های نهایی پروژه
└── README.md                            # مستندات راهنما (همین فایل)
```

### توضیح فایل‌های کلیدی
* **پوشه `final/`:** حاوی داده‌های اصلی و تفکیک‌شده کتبی زنان و زایمان در فرمت استاندارد JSONL. داده‌ها به صورت کاملاً دست‌نخورده حفظ شده‌اند.
* **فایل `docs/questions.json`:** داده نرمال‌شده، تمیز و یکپارچه در قالب استاندارد UTF-8 شامل گزینه‌های فارسی (الف، ب، ج، د)، پاسخ‌های یکسان‌سازی‌شده و آدرس‌های مبدأ (occurrences). این فایل به صورت مستقیم توسط فرانت‌اند خوانده می‌شود.

## تست و اجرای محلی
به دلیل محدودیت‌های امنیتی مرورگرها در ارسال درخواست‌های `fetch` روی پروتکل `file://`، اجرای مستقیم فایل‌های HTML با دابل‌کلیک ممکن است کار نکند. برای تست محلی از وب‌سرور داخلی پایتون استفاده کنید:

۱. ترمینال را باز کرده و وارد پوشه پروژه شوید:
   ```bash
   cd /home/hadi/gyn/hadi/gynqb
   ```

۲. سرور محلی را روی پورت ۸۰۰۰ اجرا کنید:
   ```bash
   python3 -m http.server 8000 --directory docs
   ```

۳. آدرس‌های زیر را در مرورگر خود باز کنید:
   * **سایت اصلی:** [http://localhost:8000](http://localhost:8000)
   * **پنل مدیریت:** [http://localhost:8000/admin.html](http://localhost:8000/admin.html)

## نحوه فعال‌سازی GitHub Pages
برای انتشار رایگان و اتوماتیک سایت روی سرورهای گیت‌هاب:
۱. به ریپوزیتوری خود در GitHub بروید.
۲. وارد بخش **Settings** شوید.
۳. از منوی سمت چپ، روی گزینه **Pages** کلیک کنید.
۴. در بخش Build and deployment، مقدار Source را روی **Deploy from a branch** بگذارید.
۵. شعبه (Branch) را روی **main** و پوشه را روی **/docs** قرار داده و دکمه **Save** را بزنید.
۶. پس از چند دقیقه سایت شما منتشر خواهد شد.

## راهنمای پنل مدیریت و نحوه اعمال تغییرات
پنل مدیریت (`docs/admin.html`) فاقد هرگونه Backend یا پایگاه‌داده روی سرور است تا امنیت و کارایی سرورهای استاتیک به خطر نیفتد. این پنل به صورت ۱۰۰٪ در مرورگر کاربر اجرا می‌شود.

### فرآیند ویرایش و اعمال دائمی تغییرات:
۱. **ورود داده‌ها:** پنل در زمان لود به صورت خودکار داده‌های `questions.json` را می‌خواند. همچنین می‌توانید فایل‌های JSON یا JSONL خود را با دکمه Import وارد کنید.
۲. **ویرایش و ذخیره موقت:** فیلترهای قدرتمند (مانند نمایش نیاز به بازبینی، گزینه‌های ناقص، پاسخ خالی و...) به شما در یافتن سریع خطاها کمک می‌کنند. پس از ویرایش هر سؤال، دکمه **ذخیره موقت** را بزنید تا تغییرات در آرایه جاری ذخیره شوند.
۳. **مدیریت پیش‌نویس (Draft):** با دکمه **ذخیره پیش‌نویس به سرور مرورگر**، تغییرات در `localStorage` ذخیره می‌شوند تا با رفرش یا بستن صفحه از بین نروند.
۴. **خروجی نهایی (Export):** پس از اتمام کار، با زدن دکمه‌های دانلود **JSON نهایی** یا **JSONL نهایی** نسخه اصلاح‌شده را دریافت کنید.
۵. **اعمال دائمی تغییرات:** برای دائمی‌شدن تغییرات در سایت عمومی، فایل دانلود شده را جایگزین `docs/questions.json` در پروژه کنید و سپس تغییرات را به گیت‌هاب Commit و Push کنید.

### ملاحظات امنیتی
* این پنل هیچ نام کاربری یا رمزی در فرانت‌اند برای امنیت ذخیره نمی‌کند چون امنیت واقعی سمت کلاینت با JS وجود ندارد. امنیت فایل‌ها از طریق فرآیند تایید Pull Request و دسترسی Push به ریپوزیتوری گیت‌هاب تامین می‌شود.
